
Требуется разработать приложение для управления портами на сетевых свитчах.
Цель: 
	1. Уменьшить нагрузку на отдел сетевой инфраструктуры.
	2. Уменьшить время требуемое для перенастройки портов.
	3. Дать возможность настраивать порты сотрудникам технической поддержки.
	


Требования:
	1. Приложение должно быть доступно через веб интерфейс и мобильное приложение.
	2. Пироложение должно использовать аутентификацию и авторизацию через Active Directory.
	3. Реализация должна настраивать оборудование через ssh используя учётные данные сетевого оборудования (логин и пароль).
	4. В приложение должны быть реализованы две роли: администратор и оператор.
		4.1 Администратор должен добавлять оборудование и предоставлять доступ к его настройке оператору.
		5.1 Оператор должен иметь доступ только к настройке оборудования к которому дал доступ администратор.
		
		
Варианты использования (Use Cases):
	1. Use Cases для Администратора:
		1.1 Посмотреть информацию о свитче и его портах.
		1.2 Посмотреть список свитчей.
		1.3 Настроить порт:
			1.3.1 Настроить порт как Access.
			1.3.2 Настроить порт как Trunk.
		1.4 Добавить свитч.
		1.5 Удалить свитч.
		1.6 Изменить свитч.
		1.7 Дать доступ к свитчу:
			1.7.1 На просмотр в общем списке.
			1.7.2 На детальный просмотр.
		1.8 Дать доступ на просмотр порт(а/ов) на свитче.
		1.9 Дать доступ на просмотр/изменение влана на порту определённого свитча как Access и/или Trunk.
	2. Use Cases для Оператора:
		2.1 Посмотреть информацию о свитче и его портах.
		2.2 Посмотреть список свитчей.
		2.3 Настроить порт:
			2.3.1 Настроить порт как Access.
			2.3.2 Настроить порт как Trunk.
			

Входные и выходные данные для Use Cases:
1.1 
	1.1.1 входные:
		1.1.1.1 Фильтр.
		1.1.1.2 Сортировка.
		1.1.1.3 Пагинация.
	1.1.2 выходные:
		1.1.1.1 Входной фильтр.
		1.1.1.2 Входная сортировка.
		1.1.1.3 Входная пагинация.
		1.1.1.4 Количество элементов по фильтру.

...



Входные и выходные данные будут дописаны позже.

Главное отличие выходных данных Use Caseов Оператора и Администратора в том что у Оператора нет доступа к учётным данным ни одного свитча.

В первом прототипе необходимо реализовать только Use Cases для Администратора.

Настройка свитчей должна происходить по ssh с помощью логина и пароля,
хранение информации о свитчах и списках контроля доступа временно в SQLite.
